## 1. 登录、注册与演示账号

打开站点后进入 `/login`，用用户名（或注册时用的邮箱）+ 密码登录。官方演示站：<https://who.minims.cn>（若打不开说明演示实例暂未开放，自建后同样适用本教程），演示账号见下表；演示站数据会定期重置，重要简历请导出 PDF 或自建实例保存。

本地演示环境内置两个账号：

| 账号 | 密码 | 用途 |
| --- | --- | --- |
| `demo` | `demo123` | 普通用户，已有一份完整示例简历 |
| `admin` | 首次启动时由 `MINIWHO_ADMIN_PASSWORD` 指定（无默认值，未设置且库里还没有 admin 时应用拒绝启动） | 管理员，可访问管理后台 |

> 这两个账号由后端首次启动时创建，仅用于演示。正式部署前请修改密码，或关闭演示数据初始化（见部署指南）。

### 有哪些注册方式

站点支持三种入口，**由管理员在后台「认证设置」里逐个开关**，而且默认**全部关闭**：

| 方式 | 需要什么 | 关掉时你会看到 |
| --- | --- | --- |
| 用户名注册 | 后台打开开关即可 | 登录页没有「注册」标签，只有登录框 |
| 邮箱验证码注册 | 后台打开 + 邮件通道配好（后台「通道配置」或 `MINIWHO_MAIL_*`） | 注册页不出现「邮箱」这一栏 |
| GitHub 登录 | 后台打开 + GitHub OAuth 凭据与站点对外地址配好（同上，两种来源都行） | 登录页不出现 GitHub 按钮 |

三种都没开时，登录页会直接写「当前部署未开放注册，如需账号请联系管理员开通」——这不是坏了，是自部署站点默认只给自己用的姿态。管理员要给自己之外的用户开号，可以打开用户名注册，或者直接在数据库里建号。

登录页只渲染**真的能用**的入口：开关打开了但 SMTP / GitHub 凭据没配，前台也不会出现点了必失败的按钮（后台会标出这条通道缺哪些环境变量）。

### 用用户名注册

1. 点击「注册」标签。两种注册方式同时开放时，表单上方会有「用户名 / 邮箱」切换；只开放一种时不出现切换，直接就是那一种的表单。
2. 用户名要求 3–20 位字母、数字或下划线；密码 6–32 位。
3. 勾选用户协议与隐私说明。
4. 注册成功后会自动登录，并创建一份空白简历。

### 用邮箱注册

1. 点「注册」→ 选「邮箱」这一栏（两种方式都开放时才有这个切换）。
2. 填邮箱，点「获取验证码」。邮件 1 分钟内只能要一次，同一邮箱一小时最多 5 封。
3. 填 6 位验证码（10 分钟内有效，填对一次就作废）与密码 6–32 位，昵称可留空。
4. 注册成功后自动登录并创建第一份简历；这个邮箱同时被标记为**已验证**，将来用同一个邮箱登录 GitHub 时能自动关联到这个账号。

收不到邮件通常是服务端 SMTP 没配好或授权码不对，联系管理员；验证码连错 5 次会直接作废，重新获取一封即可。

用户名由邮箱前缀自动分配，不需要你自己想，界面上显示的是昵称而不是用户名。

### 找回密码

登录页密码框下方的「忘记密码？」走的是同一条邮箱验证码链路，**只有注册时用验证码确认过的邮箱才能自助重置**：

1. 点「忘记密码？」，表单切换成重置模式，提交按钮变成「重置密码」。
2. 填注册邮箱，点「发送验证码」——和注册同一套频率规则（同一邮箱 60 秒内一封、一小时最多 5 封），但**额度按用途各算一份**，找回密码不会把注册的次数用掉；验证码 10 分钟内有效、用对一次立即作废。
3. 填 6 位验证码与**新密码**（6–32 位，不能和原密码相同），点「重置密码」。
4. 重置成功不会自动登录，界面回到登录页并把邮箱填进账号栏，用新密码登录即可；该账号在**其他设备上的会话同时被吊销**。

这三种情况自助重置走不通，只能请管理员在后台「用户管理」里点「设置新密码」：

- 用户名注册的账号——邮箱没走过验证码，属未验证。可以先在个人中心把邮箱绑上（要收新地址的验证码，见第 10 节），绑完就能自助重置。
- 用 GitHub 登录建的号，且 GitHub 主邮箱没被带出来的（没邮箱，自然收不到验证码）。同样可以先在个人中心绑一个能收信的邮箱。

> 重置会把旧凭据下的所有会话踢下线，这是设计如此：一个能被自助重置的账号，说明旧密码可能已经泄露。

### 用 GitHub 登录

点登录页的 GitHub 按钮，浏览器跳到 GitHub 授权页，同意后跳回本站并自动登录。**首次登录会自动建号**并给你一份空白简历，之后每次点同一个按钮都登进同一个账号。

- 只读取 GitHub 的主邮箱，不会拿到你的仓库、私密信息或写权限。
- 自动建的账号没有可用密码，个人中心那一栏标题因此是「登录方式」，看不到修改密码表单。想同时用密码登录有两条路：如果 GitHub 主邮箱被一并写进了账号（这条路径直接标记为已验证），用登录页的「忘记密码」给这个邮箱发验证码，重置完就有密码了；没带出邮箱时只能请管理员在后台「用户管理 → 设置新密码」。
- 如果你在本站已有一个**邮箱验证过**的账号，且它正是 GitHub 的主邮箱，GitHub 会关联到那个已有账号，而不是新建一个。
- 在 GitHub 页面点了取消，或授权页停留超过 10 分钟再回来，都会跳回登录页提示「GitHub 登录未完成」，重新点一次即可。

注册后自动生成的第一份简历标题为「我的第一份简历」，可随时重命名。

## 2. 认识「我的简历」

登录后进入 `/dashboard`。顶部导航有三项：**我的简历**、**模板中心**（官方 + 本站已分享的社区模板）、**我的模板**（你自己导入的包，导入 / 导出 / 分享都在这里）。

- **顶部数据**：简历总数（最多 50 份）、最高诊断分、待完善数量。
- **筛选**：全部 / 已完成 / 待完善；支持按标题或目标岗位搜索。
- **简历卡片**：显示模板、完整度、诊断分与最近更新时间；点击「继续编辑」进入工作台。
- **更多操作**：重命名、复制、删除。
- **新建简历**：选择标题、语言、初始模板，并可勾选「使用示例内容」快速起步。

建议针对不同岗位准备不同版本，而不是一份简历投递所有岗位。

## 3. 创建工作台

点击「新建简历」后填写：

| 选项 | 说明 |
| --- | --- |
| 简历标题 | 仅自己可见，建议写成「姓名 · 岗位」 |
| 语言 | 中文 / English，影响默认模块标题 |
| 初始模板 | 12 套模板任选，之后可随时切换 |
| 使用示例内容 | 仅在中文 + 选择时出现，会预填虚构个人资料与履历 |

创建后自动进入工作台 `/resumes/{id}`。

### 工作台布局

- **左侧**：模块导航。可拖动排序，眼睛图标控制显示 / 隐藏。
- **中间**：逐模块编辑区。点击「编辑」展开表单，「保存模块」写入云端。
- **右侧（宽屏）**：实时 A4 预览与诊断分。预览标题会显示「共 N 页」，纸面上的虚线即导出 PDF 的换页位置。
- **顶部**：简历标题、模板名、保存状态，以及「附件」「预览 / 导出」「诊断报告」「更多操作」。

窄屏下右侧预览会隐藏，可通过「预览 / 导出」查看完整 A4 效果。

### 保存机制

- 每个模块独立保存，只更新当前模块，不会覆盖其他模块。
- 保存时会携带内容版本号；如果同一份简历在另一个标签页被修改，系统会提示版本冲突，可选择保留本地修改或刷新最新内容。
- 未保存的编辑会自动暂存在浏览器本地。刷新或误关页面后，顶部会出现恢复横幅，可选择恢复或丢弃。
- 离开页面前如有未保存内容，会二次确认。

## 4. 填写简历模块

默认包含 11 个核心模块：

基本信息、求职意向、教育背景、工作经历、项目经历、在校经历、个人技能、技能熟练度、论文发表、作品集、自我评价。

其中「论文发表」默认不展示，需要时手动打开。

### 基本信息（单条目）

填写姓名、性别、手机号、邮箱、当前身份、城市、出生年月、籍贯、民族、政治面貌、婚姻状况、个人主页。

- 「展示性别」「展示出生年月」可单独控制是否出现在简历上。
- 籍贯、民族、政治面貌、婚姻状况留空就不展示；填写后会跟在城市后面排进页眉，侧栏版式单独放在「基本信息」块里。
- 分享时还可以进一步隐藏手机号、邮箱、城市、个人主页（见分享章节）。
- 个人主页必须是 `http://` 或 `https://` 开头的完整地址。

### 求职意向（单条目）

填写目标岗位、期望城市、薪资范围或「薪资面议」、求职状态。

「求职意向展示方式」有两种：

- **显示在姓名下方**（默认）：节省版面，适合经验丰富的候选人。
- **作为独立模块展示**：信息更完整，适合应届生或转岗求职。

金石模板是例外：它把求职意向固定排成一个带标题的模块，编辑页不再提供展示方式选项。

### 教育背景（多条）

每段包含学校、专业、学历、绩点、排名、院校标签、就读时间、主修课程与补充说明。

- 使用「上移 / 下移」调整顺序，建议按时间倒序。
- 「主修课程」输入后回车添加标签。
- 「院校标签」选填，可选 985 / 211 / 双一流 / 境外高校；填写后会在学校名后以朱色小角标显示，「青瓦」这类传统版式最常用。
- 「校徽」选填，可上传一张方形图片作为院校 logo，版面会把它放进院校名左侧的带框徽标栏；同模块里没上传的条目补灰色占位徽记，详见第 6 节「院校 / 公司 LOGO」。
- 教育背景不可隐藏。

### 工作经历 / 项目经历 / 在校经历（多条）

推荐使用「动作 + 做法 + 结果」结构，并尽量带数字：

> 主导订单查询链路重构，将 P95 响应时间从 820ms 降到 210ms，大促期间支撑峰值 1.2 万 QPS。

- 工作经历包含公司、职位、工作性质、城市、部门、在职时间、工作内容。
- 项目经历包含项目名称、角色、时间、项目链接、项目描述。
- 在校经历包含组织 / 团队、角色、时间、经历描述。
- 每条内容支持富文本（加粗、列表等），服务端会清洗不安全标签。
- 工作经历的「公司 LOGO」选填，与教育背景的「校徽」同一套规则：同样排在公司名左侧的带框徽标栏里，详见第 6 节「院校 / 公司 LOGO」。
- 可复制上一段快速创建相似条目。

### 个人技能 / 自我评价（单条目）

- 个人技能建议写具体技术、工具或方法，避免「沟通能力强」这类空泛描述。
- 自我评价控制在 2–3 句：经验年限、擅长方向、求职动机。

### 技能熟练度（多条）

为每项核心技能设置名称与熟练等级，适合技术人员、设计师等需要直观展示技能结构的岗位。

### 论文发表 / 作品集（单条目）

- 论文发表可填写论文、专利或研究成果；默认隐藏，填写后在模块导航中打开显示。
- 作品集填写作品名称、链接与说明，建议放最能代表能力的项目。

### 其他可选模块

在工作台底部点击「添加模块」，可添加：

考研信息、竞赛经历、获奖情况、资格证书、论文期刊、兴趣爱好、自定义模块。

- 自定义模块最多 5 个，标题可自行命名（例如「志愿服务」「开源贡献」）。
- 每个自定义模块最多 10 条内容。
- 可选模块可随时移除；移除后内容会从简历中删除，请谨慎操作。

## 5. 管理模块顺序与显示

### 调整顺序

拖动左侧导航中的模块，顺序会立即同步到简历和预览，并自动保存。

### 显示 / 隐藏

点击模块右侧的眼睛图标：

- 隐藏后模块仍保留内容，只是不出现在简历与分享页。
- 基本信息与教育背景不可隐藏。
- 论文发表等空模块默认隐藏，填写后手动打开。

### 重命名

可选模块支持自定义标题（例如把「获奖情况」改为「竞赛与荣誉」）。自定义标题只影响显示，不改变模块类型。

## 6. 附件、简历照片与条目 LOGO

### 附件简历

点击工作台顶部「附件」打开抽屉。

- 最多上传 3 个附件，单文件不超过 10MB。
- 支持 jpg、jpeg、png、pdf、doc、docx、txt。
- 系统会检查扩展名与文件头是否一致，不一致会拒绝上传：JPEG 看首三字节、PNG 看签名、PDF 看 `%PDF`、docx 看 ZIP 头、老版 doc 看 OLE2 头。只有 `txt` 没有文件头可查，直接按纯文本存储并强制浏览器以文本渲染。
- 两个已知边界：改过扩展名的文件仍然进得来（服务端只认文件头，不认内容是不是简历），任意一个 ZIP 都会被当成合法的 `.docx`。附件只对本人可见、不进公开分享页，服务端也从不执行它们，所以风险限于自己的账号里。
- 单个账号在服务器上占的总容量有上限（默认 512MB，附件、简历照片、条目图片与账号头像一并计入，回收站里的简历也算）。超限时上传会返回「账号已用 X，本次要 Y，上限 Z」，先删掉不要的文件或清空回收站再传；用量在个人中心那页能看到。
- 支持在线预览（PDF、图片、纯文本）与删除。
- 附件只属于当前账号，不会出现在公开分享页。

适合上传作品集、证书扫描件或带照片的版本。删除附件会同时删除服务器上的文件；删除整份简历时，这份简历的附件与诊断记录也会被一并清理。

### 简历照片

照片不占用附件额度，也不写进简历正文，而是走独立的头像通道。在工作台「基本信息」卡片顶部就能看到「简历照片」面板。

1. 点击「上传照片」，选择一张 JPG 或 PNG（不超过 3MB）。
2. 在裁剪弹窗里拖动图片调整位置，用滑块或滚轮缩放：证件照按 86:120 裁剪，圆形按 1:1 裁剪。
3. 点「使用这张」，服务端会把长边压到 600px 以内重新编码后保存。
4. 用「证件照 / 圆形」按钮切换展示形状，随时可以更换或移除。

要点：

- 建议用 400×500 像素以上的正面照，纯色背景效果最好。
- 每份简历只保留一张照片，新上传会覆盖旧照片；复制简历时照片会一起复制。
- 所有模板都会渲染照片，位置随版式不同：多数版式放在页眉右侧，简雅放在姓名上方的圆形徽章位，侧影与晨星放在左侧信息栏顶部。晨星、启航、青瓦三套是围绕照片设计的版式，效果最完整。
- 分享页同样会显示照片。照片链接是带签名、默认 6 小时失效的地址，别人拿到过期链接也看不到图片。
- 只接受真实编码的 JPEG / PNG，改扩展名的其他文件会被拒绝。
- 别和「账号头像」搞混：简历照片属于**这份简历**，会出现在分享页和导出的 PDF 里，删简历才带走它；账号头像属于**你这个账号**，只在站内登录后的界面显示（见「账号头像」）。两者各存各的，互不覆盖。

### 院校 / 公司 LOGO

教育背景的「校徽」和工作经历的「公司 LOGO」是两个可选的图片字段，走独立通道（不占附件额度，也不进简历正文）。在对应条目里点「上传图片」选一张 JPG 或 PNG（不超过 2MB），服务端会压到长边 256px 以内重新编码；**这一步只是暂存，要点「保存模块」才会真正落到简历上**。

显示方式在 12 套模板里是统一的，不会出现「有图没图塌一块」的情况：

所有版式都用同一套「左侧徽标栏」：版面在院校名 / 公司名左边留一个白底浅灰描边的方框，13mm 见方，金石稍大（15.1mm）。同模块里只要有一条上传了图片，每条都会留出同样宽的栏位——传了图的显示图片，没传图的画一个灰色占位徽记（教育用学士帽、工作用公文包），各条标题始终保持对齐。整个模块一条都没传时，栏位根本不存在，不会平白多出一列空框。

- 图片加载失败或文件已被回收时：回落到占位徽记，不留破图，重新上传即可。
- 建议用方形、透明背景的 PNG；带透明的会存成 PNG，其余统一转 JPEG。
- 换图或移除只改字段，旧文件由服务器在内容落库后统一回收（刚上传的图有 10 分钟宽限期，不会被误删）。所以「上传后不保存就走掉」不会丢图，也不会留下垃圾文件。
- 复制简历时 LOGO 会连同文件一起复制到新简历名下，两份简历之后各删各的，互不影响。
- 切模板不用重新上传，字段跟着简历走；分享页与导出 PDF 使用同一份图片地址，无需额外配置。

### 导入别人的模板包

上面 12 套是随应用发版的官方模板。MiniWho 还支持把别人设计的版式作为一个「模板包」（一个 `.json` 文件）导入到这套部署里，导入后它和官方模板一样免费、一样可预览、一样能导出 PDF。

预览页右侧的「样式设置 → 模板」分两组：**官方模板**（上面 12 套，随应用发版）和**社区模板**（本站里已分享的模板包，你自己导入的会标「我的」）。没有社区模板时这一组整块隐藏。导入、导出、分享都在顶部导航的**「我的模板」**页（`/my-templates`）里做，预览页和模板中心都不提供导入入口。

在「我的模板」点「导入模板包」：

1. 选择收到的 `.json` 文件；
2. 校验通过后它立刻出现在本页卡片列表里，也同时出现在预览页的社区组，点模板名即可切换；
3. 校验不通过时，弹窗会**一次列全部**不合规原因（例如「选择器必须以 .tw-acme--mypaper 开头」「url() 只接受 data: 内联资源」），改完再传，不用一条条试。

导入的规则，提前知道可以省掉大部分来回：

- 包里的 `style` 是一段纯 CSS，服务端会逐条规则重新生成后才注入页面。`<script>`、`@import`、`expression()`、`behavior`、`!important`、外链 `url()` 都会被拒绝——这是设计上的限制，不是 bug；
- 每条选择器必须以模板自己的作用域类（`tw-命名空间--编码`）开头，这样一份社区模板改不动别人的简历；
- `style` 上限 16 KB，超出请精简；
- 编码带命名空间前缀，不会和官方模板撞车；同命名空间同编码重复导入 = 升级该模板，正在用它渲染的简历会跟着换新版式。

想自己写模板包，字段表、可用的 CSS 变量与类名清单都在 [模板包格式](模板包格式.md) 里。

### 分享、导出与删除自己的模板

每张「我的模板」卡片上有两个开关和三个操作：

- **分享到模板中心**：打开后本站所有用户（包括未登录访客）都能在模板中心和预览页的社区组看到并选用它；关掉只是从公开列表下架，别人已经在用的简历照常按这套版式渲染和导出 PDF。
- **允许他人导出模板包**：只有分享后才能设置。开着时任何人（含匿名）都能下载这个包；关掉后别人只能选用，模板中心上那一行的下载按钮会变成「仅可使用」，服务端也会拒绝非作者的导出请求。
- **用它新建简历**：带着这个模板跳到「我的简历」并直接打开新建弹窗。
- **导出模板包**：下载作者提交的原始包 JSON，可以直接发给别人；不含服务端补齐的渲染字段。官方模板也能在模板中心直接导出。
- **删除**：只有导入者本人或管理员能删。如果还有简历在用这个模板，会提示「模板正在被使用」并拒绝删除——先把那些简历换成别的模板再删。

官方模板不占用「我的模板」，也不能从这里删除或分享；停用官方模板请去管理后台（见 [11. 管理后台](#11-管理后台)）。

### 样式

- **纸面滤镜**：原色 / 暖纸 / 黑白，打印同样生效。
- **正文字号**：A− / A+ 微调。
- **行距与段落**：紧 / 标准 / 松。
- **页边距**：默认「跟随模板」，每套模板自带的留白不一样（通用版式上 15mm、下 12mm，侧影与晨星另有自己的取值）。打开开关后可分上 / 右 / 下 / 左四边填毫米数（0–40），预览、浏览器打印和服务端导出会一起跟着变，续页顶部留白也按你设的值补回。
- **页脚品牌标识**：可关闭「极简简历 · MINIWHO」页脚。

页边距调的是纸面内的留白，不是打印对话框里那个「边距」——那个必须保持「无」，否则会在纸外再套一圈白边。小于 5mm 的边距导出 PDF 没问题，但多数物理打印机打不到纸边，实印可能被裁，界面会给出提示。

样式修改会自动保存，无需手动提交。

### 下载 PDF

预览页有两个导出入口：

- **下载 PDF**（主按钮）：由服务器上的无头 Chrome / Edge 直接渲染同一套 A4 版面并返回 PDF 文件，点击后浏览器直接下载，不需要手动选择打印机。首次生成约 3–6 秒，之后同样的内容与样式命中 24 小时缓存，几乎瞬时。修改内容、切换模板或更换照片都会让旧缓存失效。
- **浏览器打印**：走浏览器原生打印面板，作为通用回落路径。

如果服务器上没有可用的 Chrome / Edge / Chromium（例如精简过的容器），「下载 PDF」会提示引擎不可用并自动打开浏览器打印面板，此时：

1. 目标打印机选择 **另存为 PDF**；
2. 纸张 **A4**、边距 **无**；
3. 勾选「背景图形 / Background graphics」；
4. 保存文件。

> 两种方式的排版完全一致，因为渲染的是同一个页面，连分页位置也是同一套标记。内容超过一页时，预览纸面上会出现虚线和「第 N 页 · 共 M 页」标签，虚线所在处就是导出 PDF 的换页位置；导出前对着虚线挪动内容即可。字号与行距微调对分页同样有效。

> 下载下来的 PDF 是文字而不是图片，招聘方的 ATS 与「复制一段发给别人」都正常。少数自部署实例用 Debian 字体包时，「方、王、犬」这类偏旁会被抽成形状相近的另一个码位（看着对、复制出来不对），服务端导出会顺手把这张映射表修正掉；浏览器打印那条路用的是你自己电脑上的字体，不受影响。

| 设置 | 说明 |

- 有密码时先显示密码验证页；密码错误可重试。
- 手机号、邮箱等隐藏字段不会发送到浏览器，无法通过开发者工具还原。
- 只有开启下载权限时，才显示「保存为 PDF」按钮。
- 链接过期、被撤销或密码错误时，会显示对应提示，不会泄露简历内容。

### 评分维度

| 维度 | 分值 | 检查内容 |
| --- | --- | --- |
| 完整度 | 25 | 姓名、手机、邮箱、身份、目标岗位、教育、履历、技能、自评、作品证明 |

## 10. 个人中心

进入 `/profile`：

- 查看头像、昵称、用户名、注册时间、简历数量。
- 上传或更换账号头像（见「账号头像」）。
- 修改昵称与邮箱（用户名注册后不可改）。
- 修改密码（需原密码；新密码 6–32 位，不能与原密码相同）。
- 提交意见反馈（填写问题或功能建议，可留下联系方式）。
- 查看已诊断数量与最高分。
- 打包导出自己的全部数据，并查看磁盘用量（见「导出我的全部数据」）。
- 申请注销账号（7 天宽限期，见「注销账号」）。
- 退出当前账号。

邮箱输入框下面会标出这个地址**是否已验证**：用邮箱注册的账号天生已验证；GitHub 建的号如果带上了 GitHub 的主邮箱也算已验证；其余（注册后没填、存量手工填的）都是未验证。**改邮箱要走换绑验证**：填上新地址后先点「发送验证码」，新邮箱收到信、填码保存之后才算换绑完成，完成后的新邮箱直接就是已验证状态；未验证的邮箱不会被 GitHub 登录用来关联账号。

> **改邮箱前先确认新地址真的能收信**：换绑必须由新邮箱收一封验证码来证明归属，收不到信就完不成换绑。好处是换绑完成后验证状态不丢——自助找回密码、GitHub 邮箱关联都继续可用，不会再出现旧版「改完邮箱就找不回密码」的情况。

用 GitHub 登录建的账号没有可用密码，这一页的卡片标题会变成「登录方式」，并且不出现修改密码表单——它只能从 GitHub 进来。

修改密码后当前会话会被服务端立即吊销，需要重新登录一次；这是故意的——旧密码可能已经泄露。

### 账号头像

「账号头像」卡片管的是**你这个人**在站内的样子：这个页面顶部的大圆，和右上角账号菜单里的那个小圆。不上传时两处都显示昵称的第一个字。

- 点「上传头像」选一张 JPG 或 PNG，**原图不超过 1MB**（超了会直接提示「头像图片不能超过 1MB」，不会白跑一趟上传）；建议 400×400 像素以上，太小会被挡回来。选完先弹一个圆形裁剪框：拖动图片调整位置，滚轮或下面的滑块缩放，点「使用这张」才真正上传。
- 成功后站内立刻换图。服务端会把图缩到长边 256px 以内重编码，所以实际占的盘通常只有几十 KB，卡片上「当前 X KB」说的就是落盘后的大小。
- 换一张直接上传即可，旧的会被覆盖掉；想恢复成首字就点「移除」，确认框里写清楚了：**移除的只是账号头像，简历里的照片不受影响**。
- 它只用在站内登录后的这几个地方。访客打开分享链接看到的、导出 PDF 里的，都还是那份简历自己的照片（见「附件、简历照片与条目 LOGO」）；后台的用户列表同样不显示它。
- 两套图片是两条独立通道，各存各的：删简历不会带走账号头像，删账号头像也不碰简历照片；只有注销账号会把两者一起清掉。头像占的字节算进本账号的存储配额（见下一节）。

### 导出我的全部数据

右侧「数据与隐私」卡片底部的「导出我的全部数据」会把**这个账号在站内的所有东西**打成一个 zip 下载，链接失效、换服务器、或者打算注销之前都值得先点一次。

- 数据量大的时候按钮会显示「正在打包，数据多可能要几十秒」，不要中途关页面；zip 是边生成边传的，生成到一半断开只会得到一个不完整的下载。
- 包里有：一份 `说明.txt`（人读的目录说明）、`account.json`（昵称、邮箱、注册时间等账号信息，**不含密码**）、`resumes/<简历ID>-<标题>.json`（每份简历的完整内容，含模块顺序与样式设置）、`templates/`（你自己导入的模板包）、`files/`（附件、简历照片、条目图片与账号头像原样保留）和一份 `manifest.json`（文件清单与字节数）。
- **回收站里的简历不在导出范围内**，需要先恢复再打包；界面上那行提示说的就是这件事。
- 导出件是给人备份和迁移阅读用的，**当前版本不支持把它导回站内**——恢复只能新建简历后逐份对照着填。
- 这个接口一次能把整个账号搬走，所以限制得比别的路径紧：同一个 IP 一分钟最多 5 次。

「磁盘用量」条显示的是这个账号在上传目录里实际占的字节数（附件、简历照片、条目图片与账号头像全算，**回收站里的简历同样占盘**，因为那些文件还在）。旁边那个数字是部署方给单个账号设的上限，默认 512MB；进度条满之前就该主动删东西了——上传超限时服务端返回的是「账号已用 X，本次要 Y，上限 Z」这样的提示。部署方把上限设成 0 时不显示进度条，卡片上会写「部署者没有为单个账号设置存储上限」。

### 注销账号

「注销账号」卡片是不可回头的那一步，所以设计成两段式：

1. 点「申请注销账号」前先过身份确认：有密码的账号要**再输一次当前密码**；GitHub 建的号没有密码，改用已验证邮箱收 6 位验证码确认。
2. 提交后账号**不会立刻删除**，而是进入 7 天宽限期。这期间账号一切照常可用，只是登录后的状态行会显示「注销中」，卡片上会写明永久清除的具体时间。
3. 期内改主意了，点同一张卡片上的「取消注销」，账号和数据都保持原样，不留痕迹。
4. 到期后服务端执行硬删除：全部简历（**含回收站**）、附件、简历照片、条目图片、账号头像、自行导入的模板、未过期的邮箱验证码一并清除，分享链接同时失效，所有会话被吊销。管理员账号不能自助注销——提交时服务端直接返回「管理员账号不能自助注销，请先移交管理员或由其他管理员处理」，到期扫描里还会再挡一次，防止有人中途改了角色。

提交前请先用上一节的「导出我的全部数据」留一份备份——服务端删掉之后没有任何找回手段，数据库备份是部署方的运维文件，不是给单个用户回档用的。

## 11. 管理后台

只有 `role = admin` 的账号可以访问 `/admin`，普通用户会被重定向到「我的简历」。

### 运营概览

- 注册用户、简历总数、启用模板、诊断报告、分享链接、上传占用、待处理反馈。
- 近 7 天新增用户与简历。
- 最近注册用户列表。
- 待处理反馈预览。
- 「运行环境」卡片：右上角的状态是「全部正常 / 可用，但有降级项 / 核心依赖不可用」，下面逐条列出数据库、上传目录、PDF 渲染、邮件通道、磁盘空间五项检查与各自的实测细节；再往下是上传目录路径、磁盘剩余、附件合计与单账号上限。没装无头浏览器或没配 SMTP 只会让状态变成「有降级项」，不会报成不可用——这两件事缺失时应用照常能用（PDF 回退到浏览器打印、注册回退到用户名）。附件里出现了找不到对应简历的文件时，卡片底部会单独给一行提示并写明体量，那些是删除链路的残留，可以按目录名核对后手工清理。

这一张卡片读的是 `GET /api/admin/system`，比登录页那个公开健康检查多到很多：公开接口只回答「数据库与上传目录活着吗」，细节一概不吐；未登录访客看到 `UP` 还是 `DEGRADED`，看不出是字体没装还是发信挂了。

### 用户管理

- 搜索用户名、昵称或邮箱。
- 查看用户角色、简历数量、注册时间与状态；邮箱后面带着「已验证 / 未验证」的小标记，只有已验证的邮箱才会被 GitHub 登录用来关联账号。
- 冻结 / 恢复账号；冻结后会立即注销该用户已登录的会话，数据保留。
- 「重置密码」：给自助找回走不通的账号（邮箱未验证、或压根没绑邮箱的 GitHub 账号）直接设一个 6–32 位的新密码。保存后该账号已登录的会话会全部退出，下次登录就用这个密码——把这条告诉本人，并提醒他尽快改掉；也可以引导对方先在个人中心绑定一个能收信的邮箱，之后就能自助重置。
- 管理员不能冻结当前登录账号，也不能用这一项给自己改密码（会把自己踢下线，看起来像操作失败）；自己的密码走个人中心「修改密码」那条要验原密码的路。

### 认证设置

三个开关分别控制登录页上的三种入口，改完即存，无需额外保存按钮：

| 开关 | 打开的条件 |
| --- | --- |
| 用户名注册 | 无外部依赖，随时可开 |
| 邮箱注册 | 邮件通道就绪：后台「通道配置」或环境变量 `MINIWHO_MAIL_HOST` / `MINIWHO_MAIL_FROM` / `MINIWHO_MAIL_PASSWORD` 都算 |
| GitHub 登录 | GitHub 通道就绪：后台「通道配置」或环境变量 `MINIWHO_PUBLIC_BASE_URL` / `MINIWHO_GITHUB_CLIENT_ID` / `MINIWHO_GITHUB_CLIENT_SECRET` 都算 |

依赖没就绪时开关打不开，页面上会直接把缺的项列出来（红色的「未配置」标签），照着下方的「通道配置」填完保存就行。三个全部关闭时页面顶部有醒目提示，说明这个部署当前不提供任何自助注册。

#### 通道配置

开关下面的两张卡片就是 SMTP 与 GitHub OAuth 的凭据入口，填完点「保存」立即生效——下一次发信、下一次登录用的就是新值，**不用重启后端，也不用重拉容器**。几条规则：

- 每一项都是「后台填过的优先，没填的才回落到环境变量」，两种来源可以混着用；卡片上会写明这一组当前来自哪里（「当前由后台配置」/「当前值来自环境变量」）。
- 邮箱授权码与 Client Secret 只写不读：保存后界面上只剩「已保存」占位，想改就填新值，留空表示不改这一项。
- 想交还给环境变量，点「清空并回落到环境变量」——清掉的那一项立刻改用环境变量的值。
- 这些值明文存在 `site_settings` 表里，跟开关放在一起。谁能读到这个库，谁就拿到了你的邮箱授权码，所以数据库不要暴露到公网，库备份也不要传到公开地方。

同一页面下方会显示 GitHub 的**回调地址**（点「复制」即可）与站点对外地址。这一条要原样填进 GitHub OAuth App 的 Authorization callback URL，末尾多一个斜杠或漏掉 `/api` 都会被 GitHub 拒掉。

> 开关改动后登录页最多 30 秒才生效（公开配置接口有 30 秒缓存）。刚打开看不到入口时先等半分钟刷新，不要反复点。

### 模板管理

- 查看全部模板、分类、标签、在用简历数、来源（官方 / 导入）、版本与启用状态。
- 停用模板后，新简历不能再选择该模板；已有简历不受影响。
- 「导出全部官方模板包」下载一个 JSON 数组文件，用于部署迁移时一次性备份官方版式；每张卡片上的「导出包」只导出该模板。
- 用户导入的模板归导入者账号所有，管理员同样能在此看到并导出，接口返回的记录里带着 `visibility` 与 `exportable`。分享与导出权限只能由作者在「我的模板」页设置，管理员可以在后台停用（`status = 0`）来强制下架；删除也只能由作者或管理员在「我的模板」页做，且删不掉还有简历在用的模板。

### 首页示例简历

首页那张纸面、模板中心的缩略图和放大预览用的是同一份内容，管理员可以在后台「运营概览」的示例卡片里看到当前是哪一份简历，并在那里取消标记。

换示例的做法：打开你想当示例的那份简历，在工作台右上角「更多」菜单里点「设为首页示例」（这一项只有管理员看得到），确认后全站立即改用这份内容。

- 全站同时只有一份示例，设新的会自动取消旧的。
- 示例内容会通过不登录也能访问的接口公开，所以开启前有二次确认；请用虚构资料，别拿真实用户的简历当示例。
- 想改示例内容，就去改那份简历本身，改完最多 60 秒反映到前台（接口有 60 秒缓存）。
- 取消或删掉示例简历后，前台回落到随代码打包的出厂示例（`frontend/src/data/sampleResume.js`），那份文件只在没有设置示例时才用得到。
- 预览里的证件照**不读示例简历的头像**，而是按「基本信息 → 性别」挑随代码打包的静态照片：男 → `frontend/public/demo/avatar-male.jpg`，女 → `avatar-female.jpg`；性别留空或选「不公开」时回落到姓名首字徽标。这样首页与模板中心那十几张缩略图不用去抢签名头像链接，也不会放着放着过期。想换示例照片，直接替换这两张图即可。

### 意见反馈

- 按全部 / 待处理 / 已处理筛选。
- 查看反馈内容与联系方式，填写管理员回复。
- 保存回复后，反馈标记为已处理，并在列表中展示回复内容。

> 用户侧只提供反馈提交入口，暂不支持查看历史反馈或管理员回复；回复保存在后台记录中。

## 12. 常见问题

### 页面提示「无法连接服务器」

确认后端已启动并监听 8080 端口，或检查 Nginx 的 `/api` 代理是否指向正确容器 / 地址。

### 登录后立刻回到登录页

登录令牌可能存在过期或无效，清理浏览器 `localStorage` 中的 `miniwho.token`、`miniwho.user` 后重新登录。生产环境请检查服务器时间是否准确。

### 保存时提示版本冲突

同一份简历在另一个标签页被修改。选择「保留本地修改」会重新提交当前草稿，选择「刷新」会丢弃本地草稿并加载最新版本。

### 富文本里贴入的图片 / 视频没有保存

出于安全与体积考虑，只保留段落、换行、加粗、斜体、下划线、删除线、有序 / 无序列表等基础标签，其余 HTML 会被服务端移除。

### 打印出来有白边或分页位置不对

在打印面板中把纸张设为 A4、边距设为「无」，并开启「背景图形」。Chrome / Edge 的效果最好。

设成「无」之后纸面上仍有留白，那是简历自己的页边距（见 [样式](#样式) 里的「页边距」），打印面板管不到它；想要更满的版面就在工作台里把它调小，但别低于 5mm，否则实印会被打印机裁掉。

### 分享链接被隐藏的手机号还能恢复吗

不能。隐藏字段在服务端被移除后再返回给访客，浏览器端没有这些数据。创建者自己预览时仍能看到完整内容。

### 登录页没有注册入口

正常现象：用户名注册、邮箱注册、GitHub 登录三种入口默认全部关闭，由管理员在后台「认证设置」里逐个打开。页面提示「当前部署未开放注册，如需账号请联系管理员开通」时，找管理员开通或直接请管理员建号。

### 后台打开了开关，登录页还是看不到入口

两种方式要同时满足「开关打开」和「通道凭据配好」：邮箱注册要 SMTP 通道，GitHub 登录还要站点对外地址。后台那条开关上会列出缺哪些项，在下方「通道配置」里补齐并保存就好，不用重启后端。都配好了则再等半分钟——公开配置的接口有 30 秒缓存。

### 收不到注册验证码

先确认不是垃圾箱：验证码邮件是 HTML 排版的，个别邮箱会把它归到广告或推广一栏。若确实没收到，多半是部署方的 SMTP 没配好（授权码填错、SMTP 服务没在邮箱网页端开启），这只能由管理员排查；用户侧能遇到的其它原因是提示「该邮箱已注册」（邮箱已被别的账号占用）和「操作太频繁」（60 秒内重复申请、或一小时内已超过 5 封）。

### 用 GitHub 登录进来是个空账号

如果原来那个本站账号的邮箱是注册后手工填的、没走过验证码，GitHub 不会自动关联它（防止别人用同一个邮箱接管账号），而是新建一个账号。用密码登录原账号即可，两个账号需要手工合并时联系管理员。

### 点 GitHub 登录直接报错或被踢回登录页

授权页点了取消、或停留超过 10 分钟才回来都会失败，重新点一次即可。如果每次都在 GitHub 报 `redirect_uri_mismatch`，是部署方在 GitHub OAuth App 里填的回调地址与后台「认证设置」显示的那条不一致。

### 忘记密码

登录页点「忘记密码？」，用注册邮箱收 6 位验证码自助设置新密码，全程不需要联系任何人。前提是**这个邮箱验证过**——邮箱注册的账号天生满足；用户名注册或 GitHub 建的账号只要在个人中心完成过一次换绑验证（新地址收码确认）也算。都没满足的话只能请管理员在后台「用户管理 → 重置密码」。详见第 1 节「找回密码」。

### 找回密码时提示「该邮箱未验证」

自助重置只认已验证的邮箱，未验证的一律拒绝（否则任何人填一个陌生邮箱就能改掉别人的密码）。常见的未验证情形是注册后手工填的邮箱。解决办法两选一：在个人中心把邮箱换成能收信的地址并完成换绑验证（新地址收码确认，见第 10 节），或让管理员在后台设一个新密码。

### 上传附件提示「账号已用 X，本次要 Y，上限 Z」

单个账号在服务器上占的容量到了部署方设的上限（默认 512MB）。这个额度算的是磁盘上的实际文件，回收站里的简历同样占盘，所以先清空回收站往往就够用了。个人中心的「磁盘用量」条能看到当前占用；确实需要更大额度只能让部署方调 `MINIWHO_STORAGE_QUOTA_MB`（见部署指南）。

### 提示「操作太频繁，请一分钟后再试」

登录、注册、找回密码、导出账号数据这些接口按 IP 限流，一分钟内超了次数就会这样提示。等 60 秒重试即可；反复出现说明你所在的网络出口是一个共享 IP（公司 NAT、代理），换个网络或让管理员在反代层再加一道缓存。

### 数据保存在哪里

- SQLite：`backend/miniwho.db`（默认）。
- MySQL：`DB_HOST` / `DB_NAME` 指定的数据库。
- 附件：`MINIWHO_UPLOAD_DIR`，默认 `backend/uploads/`。

备份时请同时备份数据库与附件目录。具体操作见 [部署指南](部署指南.md)。
