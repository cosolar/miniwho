# 新手应用镜像快速部署教程

> 目标：**不装 Java、不装 Node、不碰数据库**，用已经发布好的镜像把「极简简历 MiniWho」跑起来。
> 全程复制粘贴即可，第一次做大约 20–30 分钟。
>
> 本教程统一用 `cosolar/miniwho:latest`，它始终指向最新发布版，不用记版本号。想锁定某个版本时，把 `latest` 换成 Docker Hub 上的具体标签即可（仓库页 <https://hub.docker.com/r/cosolar/miniwho/tags>）。

---

## 0. 先选一条路

| 你想做什么 | 选哪个方案 | 用什么数据库 | 大概耗时 |
| --- | --- | --- | --- |
| 先在本机看看效果 | **方案 A**（单容器 + SQLite） | SQLite（镜像内置） | 5 分钟 |
| 放到云服务器上长期用、给域名访问 | **方案 B**（Compose + MySQL） | MySQL 8 | 20 分钟 |
| 服务器上已经有 1Panel / 宝塔 | 方案 B 起服务，再用面板配域名和 HTTPS | 建议 MySQL | 20 分钟 |

两个方案用的是**同一个镜像**，数据格式也兼容；方案 A 试完想转正式，按方案 B 重新部署即可（简历数据需要另外迁移，见 4.6）。

## 1. 准备清单

开始前确认这几样：

- [ ] 一台机器：自己的电脑（Windows / macOS）或一台 Linux 云服务器
- [ ] 云服务器配置：**2 核 4G 起**（最低 2 核 2G，但导出 PDF 时会吃内存）
- [ ] 磁盘：至少 20GB 空闲（镜像本身约 1.2GB）
- [ ] 一个**固定的**随机长字符串，后面叫 `MINIWHO_MEDIA_SECRET`
- [ ] 一个管理员强密码
- [ ] （正式上线才需要）一个已经解析到你服务器的域名

关于 `MINIWHO_MEDIA_SECRET`：它用来给头像、照片的访问链接签名。随便生成一串 64 位随机字符记下来，**之后不要改**；改了以后历史头像链接会全部失效。

Linux / macOS 生成：

```bash
openssl rand -hex 32
```

Windows 没有 `openssl`，用 PowerShell 生成两次 GUID 拼起来也行：

```powershell
[guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
```

## 2. 安装 Docker

### 2.1 Linux 服务器

Ubuntu / Debian / CentOS 都可以用官方脚本：

```bash
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
docker version
```

能同时看到 `Client` 和 `Server` 两段就说明装好了。如果提示 `permission denied`，把当前用户加进 docker 组（重新登录生效）：

```bash
sudo usermod -aG docker $USER
```

> 服务器在国内拉 Docker Hub 常常很慢，装完先按 2.3 配好加速器。

### 2.2 Windows / macOS

1. 去 Docker 官网下载 **Docker Desktop** 并安装；
2. 打开 Docker Desktop，等左下角状态变成 running；
3. 打开终端（Windows 用 PowerShell），执行 `docker version` 确认有 `Server` 段。

Windows 第一次启动可能会提示开启 WSL2，按提示点确定、重启一次即可。

### 2.3 拉不动镜像怎么办

国内直连 Docker Hub 经常超时。给 Docker 配一个镜像加速地址（腾讯云、阿里云容器镜像服务都能拿到专属地址），Linux 上编辑 `/etc/docker/daemon.json`：

```json
{
  "registry-mirrors": ["https://你的加速地址"]
}
```

```bash
sudo systemctl restart docker
docker pull cosolar/miniwho:latest
```

能拉下来再继续。云服务器上如果已经装过 1Panel，它的「容器 → 镜像加速」里可以直接配置。

> 镜像只有 `linux/amd64` 架构。Apple Silicon（M 系列芯片）的 Mac 需要加 `--platform linux/amd64` 走模拟，会慢一些。

## 3. 方案 A：本机 5 分钟试跑（SQLite）

适合先在电脑上体验：一个容器，数据库用镜像内置的 SQLite，不额外装任何东西。

### 3.1 一条命令启动

Linux / macOS（Windows PowerShell 把 `$(openssl rand -hex 32)` 换成第 1 节里自己生成的那串随机字符）：

```bash
docker run -d --name miniwho \
  -p 8088:8080 \
  -v miniwho-uploads:/app/uploads \
  -e MINIWHO_DB=/app/uploads/miniwho.db \
  -e MINIWHO_ADMIN_PASSWORD='换成你的管理员强密码' \
  -e MINIWHO_DEMO_PASSWORD='换成演示账号密码' \
  -e MINIWHO_MEDIA_SECRET="$(openssl rand -hex 32)" \
  -e TZ=Asia/Shanghai \
  --shm-size=512m \
  cosolar/miniwho:latest
```

几个参数的作用：

| 参数 | 作用 |
| --- | --- |
| `-p 8088:8080` | 浏览器访问 `8088`，容器内部是 `8080`；`8088` 被占用就换一个 |
| `-v miniwho-uploads:/app/uploads` | 把数据放在 Docker 卷里，删容器不丢数据 |
| `-e MINIWHO_DB=...` | **不能省**。默认数据库路径不在卷里，删容器时数据库会一起消失 |
| `-e MINIWHO_ADMIN_PASSWORD=...` | 管理员 `admin` 首次创建时的密码，之后改这里不再生效 |
| `-e MINIWHO_MEDIA_SECRET=...` | 头像链接签名密钥，必须是固定值 |
| `--shm-size=512m` | 无头 Chromium 导出 PDF 需要共享内存，不要删 |

### 3.2 打开页面并登录

浏览器访问 **http://localhost:8088**（服务器上是 `http://服务器IP:8088`）。

首次启动会自带：

- 管理员账号：`admin`，密码就是上面 `MINIWHO_ADMIN_PASSWORD` 填的值；
- 演示账号：`demo`，密码是 `MINIWHO_DEMO_PASSWORD` 填的值，带一份完整的示例简历。

登录后先做两件事：

1. 右上角进入「个人中心 → 修改密码」，把管理员密码改成你记得住的强密码；
2. 访问 `/admin`，看一眼「站点设置」：**注册通道默认全是关的**，也就是说这个站默认只有你自己能注册、能登录，适合纯自用；要开放给别人，再配置 SMTP 或 GitHub 登录后打开开关。

### 3.3 停止、重启、删除

```bash
docker stop miniwho        # 停止，数据保留
docker start miniwho       # 再启动
docker logs -f miniwho     # 看日志，Ctrl+C 退出
docker rm -f miniwho       # 删除容器，miniwho-uploads 卷还在
```

彻底重置（**会删掉所有简历和附件**）：

```bash
docker rm -f miniwho
docker volume rm miniwho-uploads
```

### 3.4 备份

数据全在 `miniwho-uploads` 卷里（数据库 + 附件），整卷打包即可：

```bash
docker run --rm \
  -v miniwho-uploads:/data:ro \
  -v "$PWD":/backup \
  alpine tar czf /backup/miniwho-$(date +%F).tar.gz -C /data .
```

恢复时把容器停掉，用备份包覆盖回卷里，再启动容器。

> SQLite 适合单人自用。要给多个人同时用、经常导出 PDF，请直接上方案 B 的 MySQL。

## 4. 方案 B：云服务器正式部署（Compose + MySQL）

### 4.1 放行端口

在云服务器的「安全组」里放行 `8088`（或者你后面要用的 `80` / `443`）。如果服务器开了 `ufw` / `firewalld`，也要一起放行。

### 4.2 建目录、写两个文件

```bash
sudo mkdir -p /opt/miniwho && cd /opt/miniwho
```

新建 `docker-compose.yml`：

```yaml
services:
  mysql:
    image: mysql:8.4
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: miniwho
      MYSQL_USER: miniwho
      MYSQL_PASSWORD: ${DB_PASSWORD}
      TZ: Asia/Shanghai
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
    volumes:
      - mysql-data:/var/lib/mysql
    healthcheck:
      test: ["CMD-SHELL", "mysqladmin ping -h 127.0.0.1 -u root -p$$MYSQL_ROOT_PASSWORD --silent"]
      interval: 10s
      timeout: 5s
      retries: 12
      start_period: 30s

  app:
    image: cosolar/miniwho:latest
    restart: unless-stopped
    environment:
      SPRING_PROFILES_ACTIVE: mysql
      DB_HOST: mysql
      DB_PORT: "3306"
      DB_NAME: miniwho
      DB_USER: miniwho
      DB_PASSWORD: ${DB_PASSWORD}
      MINIWHO_UPLOAD_DIR: /app/uploads
      MINIWHO_SEED_DEMO: ${MINIWHO_SEED_DEMO:-true}
      MINIWHO_MEDIA_SECRET: ${MINIWHO_MEDIA_SECRET}
      MINIWHO_ADMIN_PASSWORD: ${MINIWHO_ADMIN_PASSWORD}
      MINIWHO_DEMO_PASSWORD: ${MINIWHO_DEMO_PASSWORD}
      MINIWHO_CORS_ORIGINS: "*"
      TZ: Asia/Shanghai
    shm_size: "512mb"
    volumes:
      - uploads:/app/uploads
    depends_on:
      mysql:
        condition: service_healthy
    ports:
      - "8088:8080"
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://127.0.0.1:8080/api/health || exit 1"]
      interval: 15s
      timeout: 5s
      retries: 10
      start_period: 40s

volumes:
  mysql-data:
  uploads:
```

同目录再新建 `.env`（Compose 会自动读取），把等号右边换成你自己的值：

```dotenv
MYSQL_ROOT_PASSWORD=换成一串强密码
DB_PASSWORD=换成一串强密码
MINIWHO_ADMIN_PASSWORD=换成一串强密码
MINIWHO_DEMO_PASSWORD=换成一串强密码
MINIWHO_MEDIA_SECRET=换成第 1 节生成的那串固定随机字符
MINIWHO_SEED_DEMO=true
```

两个小提醒：

- 密码里**尽量别用 `$`**。Compose 会把 `$` 当变量展开，必须用时得写成 `$$`，很容易踩坑。
- `.env` 里有明文密码，执行 `chmod 600 .env`，也不要提交到任何 git 仓库。

### 4.3 启动并检查

```bash
docker compose up -d
docker compose ps
```

第一次启动时 MySQL 要初始化 30–60 秒，`app` 会短暂显示 `Created` 或 `health: starting`，这是正常的。等两分钟再检查：

```bash
curl -fsS http://127.0.0.1:8088/api/health
```

返回 `"status":"UP"` 就成功了。返回内容里还会列出数据库和上传目录两项检查。

如果 `docker compose ps` 里 `app` 一直是 `unhealthy` 或反复重启：

```bash
docker compose logs --tail=100 app
docker compose logs --tail=50 mysql
```

绝大多数情况是密码填错、端口被占用或内存不足（见第 7 节）。

### 4.4 首次登录与安全设置

1. 浏览器打开 `http://服务器IP:8088`，用 `admin` + `MINIWHO_ADMIN_PASSWORD` 登录；
2. 立刻去「个人中心」改密码；
3. 进 `/admin`，按需设置：
   - **站点设置 → 内容宽度**：全站页面最大宽度，默认 1200px，可调 1100–1600px；
   - **站点设置 → 注册通道**：邮箱注册 / GitHub 登录 / 用户名注册，默认全关。邮箱注册需要先在同一个页面把 SMTP 参数填好；
   - **意见反馈**、**用户管理**、**模板管理** 都在同一个后台。
4. 确认不需要演示内容后，把 `MINIWHO_SEED_DEMO` 设为 `false` 并 `docker compose up -d`（这个开关只停止后续初始化，不会删掉已有的 `demo` 账号）。

### 4.5 日常运维四条命令

```bash
docker compose ps                 # 看状态
docker compose logs -f --tail=100 app   # 看日志
docker compose restart app        # 重启应用
docker compose down               # 停止并删除容器（数据卷保留）
```

> 千万不要用 `docker compose down -v`，那会连数据库和附件一起删掉。

### 4.6 备份与恢复

备份数据库和附件：

```bash
cd /opt/miniwho
docker compose exec -T mysql sh -c \
  'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines --triggers "$MYSQL_DATABASE"' \
  > miniwho-$(date +%F).sql

docker run --rm \
  -v miniwho_uploads:/data:ro \
  -v "$PWD":/backup \
  alpine tar czf /backup/miniwho-uploads-$(date +%F).tar.gz -C /data .
```

卷名默认是「目录名 + `_uploads`」；目录不叫 `miniwho` 时，用 `docker volume ls` 查一下实际的卷名。

恢复顺序：先 `docker compose stop app`，导入 SQL、把附件解回卷，再 `docker compose start app`。

## 5. 绑定域名与 HTTPS

`http://IP:8088` 只适合自己用。给别人访问、要生成分享链接，建议挂一个域名并开启 HTTPS。

### 5.1 已有 1Panel / 宝塔

在面板里新建一个「反向代理」站点：

- 域名：`who.你的域名.com`
- 上游地址：`http://127.0.0.1:8088`
- 顺手申请免费证书，开启 HTTPS

面板会自动处理 `Host`、`X-Forwarded-*` 头，不用改应用配置。如果面板的 Nginx / OpenResty 跑在容器里、访问不到 `127.0.0.1`，把上游换成宿主机的内网地址（例如 `http://172.17.0.1:8088`）。

### 5.2 用 Caddy（自动 HTTPS，最省事）

服务器上装好 Caddy 后，`/etc/caddy/Caddyfile` 加三行：

```caddyfile
who.你的域名.com {
    reverse_proxy 127.0.0.1:8088
}
```

```bash
sudo systemctl reload caddy
```

Caddy 会自己申请并续期证书。

### 5.3 用 Nginx

```nginx
server {
    listen 443 ssl http2;
    server_name who.你的域名.com;

    # ssl_certificate / ssl_certificate_key 按你的证书路径填写

    client_max_body_size 20m;   # 附件最大 10MB，留点余量

    location / {
        proxy_pass http://127.0.0.1:8088;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

配好域名后，记得回后台「站点设置」把**站点对外地址**填成 `https://who.你的域名.com`——邮件里的链接、GitHub 登录回调都要用它。

> 配了反代以后，建议把 `8088` 从公网安全组里收掉，只让反代走内网访问，避免有人绕过 HTTPS 直连。

## 7. 常见问题

**1. `docker: command not found` 或 `permission denied`**

Docker 没装好，或者当前用户不在 `docker` 组。回第 2 节，执行完 `usermod` 后要重新登录一次。

**2. `docker pull` 一直超时**

国内网络访问 Docker Hub 不稳，按 2.3 配镜像加速。已经配了还是慢，可以换一个加速地址再试。

**3. 端口 8088 被占用**

```bash
sudo ss -lntp | grep 8088
```

要么停掉占用的程序，要么把 `-p 8088:8080` 改成 `-p 8090:8080`，访问地址也跟着改。

**4. 容器一直 `unhealthy` 或反复重启**

先看日志：`docker compose logs --tail=100 app`。常见原因：

- `.env` 里的密码为空，或者 `MINIWHO_MEDIA_SECRET` 没填；
- MySQL 还在初始化，等一两分钟；
- 内存不够，Chromium 或 JVM 被系统杀掉——给服务器加内存或加 swap。

**5. 页面正常，但导出 PDF 失败**

服务端 PDF 用无头 Chromium 渲染，比较吃内存。先确认容器至少有 1GB 可用内存；内存紧张时可以把 `MINIWHO_PDF_MAX_CONCURRENT` 设为 `1`。

即使服务端 PDF 不可用，前端也会自动回落到「浏览器打印 → 另存为 PDF」，功能不会中断。

**6. 重启之后头像全部裂开**

`MINIWHO_MEDIA_SECRET` 变了。它是链接签名密钥，必须是一个固定值；用 `docker run` 时每次执行 `openssl rand` 都会变，记得把值存下来。

**7. 登录时报 `403 Invalid CORS request`**

多半是自己改过 `MINIWHO_CORS_ORIGINS`，而浏览器的来源不在列表里。官方镜像默认 `*`，不用改；要收紧的话，把正式域名（含 `https://`）加进去：

```dotenv
MINIWHO_CORS_ORIGINS=https://who.你的域名.com
```

**8. 登录页没有「注册」按钮**

注册通道默认全关。去 `/admin` →「站点设置」打开；邮箱注册还要先把 SMTP 配好，否则验证码发不出去。保存后登录页最多 30 秒刷新。

**9. 忘了管理员密码**

用 MySQL 部署时，先在前台注册一个新账号，再在数据库里把它提升为管理员：

```bash
docker compose exec -T mysql sh -c \
  'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"' <<'SQL'
UPDATE users SET role = 'admin', updated_at = UNIX_TIMESTAMP() * 1000 WHERE username = '你的用户名';
SQL
```

然后用这个账号登录 `/admin`。SQLite 部署的镜像里没有 `sqlite3` 命令，建议一开始就把管理员密码存进密码管理器，并保留备份。

**10. Mac（M 系列芯片）拉不到镜像或起不来**

镜像只有 `linux/amd64`。在 `docker run` / compose 里加 `platform: linux/amd64`（或 `--platform linux/amd64`），走 Rosetta 模拟。

## 8. 升级与回滚

升级前**先备份**（4.6）。

用 `latest` 标签时不用改任何文件，直接拉最新镜像重建容器：

```bash
docker compose pull app
docker compose up -d
docker compose logs -f --tail=100 app
```

如果你在 `docker-compose.yml` 里锁定的是具体版本号，就先把 `image:` 那一行改成 Docker Hub 上的新标签，再执行上面三条命令。版本列表见 <https://hub.docker.com/r/cosolar/miniwho/tags>。

启动后重新过一遍第 6 节的检查清单。表结构变更由应用启动时自动完成，不需要手工执行 SQL。

想回滚就把 `image:` 改回旧版本标签（用 `latest` 的话，改成出问题时的那一版），再 `docker compose up -d`。**如果新版做过表结构变更，回滚时要连数据库备份一起恢复**，所以升级前的备份不能省。

## 9. 环境变量速查

| 变量 | 是否必填 | 说明 |
| --- | --- | --- |
| `MINIWHO_ADMIN_PASSWORD` | 必填 | `admin` 首次创建时的密码；账号存在后改它不再生效 |
| `MINIWHO_DEMO_PASSWORD` | 建议 | `demo` 演示账号密码 |
| `MINIWHO_MEDIA_SECRET` | 必填 | 头像 / 照片链接签名密钥，固定值，改了就失效 |
| `MINIWHO_DB` | SQLite 必填 | 数据库文件路径，必须放在卷里 |
| `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASSWORD` | MySQL 必填 | 数据库连接信息 |
| `MINIWHO_UPLOAD_DIR` | 建议 | 上传目录，官方镜像里是 `/app/uploads` |
| `MINIWHO_CORS_ORIGINS` | 可选 | 默认 `*`；收紧时填浏览器访问域名 |
| `MINIWHO_STORAGE_QUOTA_MB` | 可选 | 单账号上传上限，默认 512MB，`0` 表示不限 |
| `MINIWHO_PDF_MAX_CONCURRENT` | 可选 | 同时渲染 PDF 的数量，默认 2；小内存机器改 1 |
| `MINIWHO_PUBLIC_BASE_URL` | 可选 | 站点对外地址，例如 `https://who.你的域名.com` |
| `TZ` | 建议 | 时区，填 `Asia/Shanghai` |

完整清单、邮件和 GitHub 登录的配置方式，见 [部署指南](部署指南.md)；日常使用说明见 [使用教程](使用教程.md)。
