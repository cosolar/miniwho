# 模板包格式

这份文档写给两类人：想**导入别人模板 / 分享自己模板**的用户，以及想给项目**新增一套官方模板**的贡献者。

想从零做一套主题（选骨架、写 CSS、验分页、提交分享）请看 [模板主题开发指南](模板主题开发指南.md)，里面有配方库和踩坑清单；本文只管格式与校验规则。

接口层面的请求与响应见 [API.md](API.md) 第 3 章；部署时模板怎么备份迁移见 [部署指南.md](部署指南.md)。

---

## 1. 一套模板由三层组成

| 层 | 内容 | 归谁管 | 能不能用模板包分享 |
| --- | --- | --- | --- |
| L0 骨架 | 简历的 DOM 结构与 A4 分页算法 | 代码（`ResumePaper.vue` / `PaperSection.vue` / `paperPagination.js`） | ❌ 不在包里 |
| L1 令牌 | 版式名、主色、字体、模块标题样式、是否放照片 | 模板包 `theme` / `capability` | ✅ |
| L2 样式 | 在骨架上叠加的自定义 CSS | 模板包 `style`，**服务端净化后**才生效 | ✅ |

包里没有、也永远不会有的东西：**JavaScript 与 HTML**。渲染端只读服务端展开并净化过的 `config`，包原文（`pkg`）只用于导出交换。这样一份社区模板最坏情况只能改坏它自己的简历版面，改不动站点、也碰不到别人的数据。

## 2. 包结构

```json
{
  "api": 1,
  "id": { "namespace": "lin", "code": "mudan", "version": "1.0.0" },
  "meta": {
    "name": "木丹",
    "description": "在极简单栏上叠一层紫红色侧标，模块标题加粗左对齐。",
    "category": "社区",
    "tags": ["单栏", "社区", "紫红"],
    "author": "郝简历",
    "license": "MIT"
  },
  "theme": {
    "layout": "minimal",
    "accent": "#7c3aed",
    "font": "serif",
    "sectionStyle": "caps",
    "density": "standard"
  },
  "capability": { "photo": false, "free": true },
  "sortWeight": 900,
  "style": ".tw-lin--mudan .paper-section__title {\n  color: #7c3aed;\n  border-left: 3px solid #7c3aed;\n  padding-left: 6px;\n}\n"
}
```

字段规则（校验器 `TemplatePackageCodec` 逐条执行，**所有问题一次返回**）：

| 路径 | 必填 | 限制 | 说明 |
| --- | --- | --- | --- |
| `api` | ✅ | 必须等于 `1` | 渲染器契约版本；不认识的包直接拒绝，不会半渲染 |
| `id.namespace` | ✅ | `^[a-z][a-z0-9-]{1,59}$` | 你的标识（GitHub 用户名、站点名等），`official` 保留给内置包 |
| `id.code` | ✅ | `^[a-z][a-z0-9-]{1,49}$` | 包名；两者合成落库编码 `namespace--code`，所以两个人都叫 `mudan` 也能共存 |
| `id.version` | ✅ | 语义化 `x.y.z` | 只作展示与文件名用，同作者重复导入按升级原地覆盖 |
| `meta.name` | ✅ | ≤ 100 | 界面上显示的名字 |
| `meta.description` | ✅ | ≤ 500 | 一句话说清适合什么场景 |
| `meta.category` | ✅ | ≤ 30 | 模板中心的筛选标签，自由文本 |
| `meta.tags` | ⬜ | 每项 ≤ 20，最多 8 项 | 搜索用 |
| `meta.author` | ⬜ | ≤ 100 | 分享者署名，界面上会显示 |
| `meta.license` | ⬜ | ≤ 60 | 建议 `MIT` 或 `CC-BY-4.0` |
| `theme.layout` | ✅ | 见 §3 | 骨架版式 |
| `theme.accent` | ✅ | `#rrggbb` | 主色 |
| `theme.font` | ✅ | `sans` / `serif` | 正文字体族 |
| `theme.sectionStyle` | ✅ | 见 §3 | 模块标题样式 |
| `theme.density` | ⬜ | 目前只接受 `standard` | 占位字段，字号与行距由用户在预览页调 |
| `capability.photo` | ⬜ | 默认 `false` | `true` 时模板会留出证件照位 |
| `capability.free` | ⬜ | 默认 `true` | 本项目全部免费，留这个键是给未来的市场 |
| `sortWeight` | ⬜ | 0–9999，默认 0 | 官方列表排序，越小越靠前 |
| `style` | ⬜ | ≤ 16384 字符 | L2 自定义 CSS，规则见 §4 |
| `sample` | ⬜ | JSON 对象，≤ 200,000 字符 | 模板自带的预制示例数据（完整简历 `content`，只做结构校验）。新建简历勾选「使用示例数据」时优先于全局示例；不进渲染 `config`，只随包导出 |

## 3. 渲染器能力清单

`theme` 只能填下面这些值，它们对应代码里已经实现好的类：

- **`layout`**（`ResumePaper.vue` 里的 `.layout-*`）：
  `minimal` 单栏留白 · `academic` 学术细线 · `sidebar` 双栏 · `band` 顶部色带 · `center` 居中页眉 · `timeline` 时间轴 · `profile` 头像单栏 · `classic` 经典学术 · `rail` 通栏照片侧栏 · `photoheader` 照片页眉 · `formal` 传统中文单栏 · `ribbon` 斜切色带 + 旗标
- **`sectionStyle`**（`PaperSection.vue` 里的 `.paper-style-*`）：
  `line` 细下划线 · `caps` 字距放大标题 · `bar` 左侧竖条 · `block` 色块底 · `dot` 圆点 · `rule` 通栏细线 · `icon` 图标 + 虚线 · `flag` 旗标
- **`font`**：`sans` / `serif`

这三处是同一份清单的三个副本，加新值时必须一起改：

1. `ResumePaper.vue` 的 `.layout-*`（或 `PaperSection.vue` 的 `.paper-style-*`）——真正画出来的东西；
2. `backend/.../template/RendererCapabilities.java`——校验器认识的合法值；
3. 本文档的清单。

只改前两处，导入接口会把新值当非法值拒绝；只改后两处，包能导入但页面上没有对应样式。

## 4. `style` 字段的规则

服务端 `TemplateCssSanitizer` 不是「过滤后原样回显」，而是**解析后重新生成**：注释会被去掉，格式会被规范化，作者原文里的任何夹带都进不了产物。

必须满足：

- **每条选择器都以模板自己的作用域类开头**，形如 `.tw-lin--mudan ...`。作用域类 = `tw-` + 落库编码，导入接口会把它连同净化后的 CSS 一起写进 `config.scopeClass` / `config.styleCss`。
  写 `.paper-section { }` 会被拒绝；写 `.tw-lin--mudan-x { }` 也算越界（前缀边界检查）。
- 属性名只能是标准属性或 CSS 自定义属性（`--paper-accent` 这类），不接受 `*zoom` 之类的 hack。
- `url()` 只接受 `data:` 内联资源。外链会被拒绝——导出 PDF 不该依赖别人的服务器，那也是隐私面。内联的 SVG 必须百分号编码（字面 `<` 会被拒）；用它替换模块图标、以及怎么让它跟着主题上色，见[开发指南](模板主题开发指南.md) 4.7。
- 允许 `@media` / `@supports`，且只能嵌套一层；`@import`、`@keyframes`、`@font-face` 等一律拒绝。
- 禁止 `!important`、`expression(`、`javascript:`、`behavior:`、`-moz-binding`，以及任何包含 `<` 的内容（防跳出 `<style>`）。
- 至少要有**一条**能保留的规则，全被过滤空的 `style` 会直接报错，而不是静默导入一个没样式的模板。

关于特异度：内置模板样式是 Vue scoped 样式，净化后的包 CSS 在运行时插到 `<head>` 末尾，**打平时包 CSS 胜出**。所以调颜色、间距、边框这类不需要 `!important`（它也被禁了）；要覆盖内置里带 `.layout-xxx` 的复合选择器时，写得更具体一层即可。

可用的 CSS 变量（骨架在根节点上算好，直接改比硬写数值稳）：

| 变量 | 含义 | 默认来源 |
| --- | --- | --- |
| `--paper-accent` | 主色 | `theme.accent` |
| `--paper-font-family` | 正文字体 | `theme.font` |
| `--paper-base-size` | 正文基准字号 | 用户在预览页调 |
| `--paper-line-height` | 行高 | 用户调 |
| `--paper-section-gap` | 模块间距 | 用户调 |

常选择到的骨架类名：

```
.resume-paper            根节点（同时带 .layout-*、.filter-*、.tw-<你的编码>）
  .paper-header / .paper-header__main / .paper-name / .paper-role / .paper-identity
  .paper-contacts / .paper-contact / .paper-contact__label
  .paper-photo / .paper-monogram / .paper-rail / .rail-* / .sidebar-aside / .sidebar-main
  .paper-content / .paper-flow / .paper-section
    .paper-section__title / .paper-section__icon / .paper-section__body
    .paper-item / .paper-item-head / .paper-item-title / .paper-item-period / .paper-item-sub / .paper-item-tag
    .paper-item-mark（教育 / 工作条目的左侧徽标栏，所有版式都有）
    .paper-rich / .paper-note / .paper-facts / .paper-skill / .paper-skill__dots
  .paper-footer
```

**条目 logo（`fields.logo`）**：教育背景与工作经历的条目可以各挂一张图片，所有版式都把它排进条目左侧的带框徽标栏 `.paper-item-mark`——白底、`0.25mm` 浅灰描边，金石 15.1mm 见方，其余版式 13mm。同模块里只要有一条传了图，每条都会多出这个节点：有图的放 `<img>`，没图的放占位图标，整模块一条都没传时节点不存在，不会凭空多一列空框。徽标栏是「骨架自带」的行为，`style` 里没有对应钩子可改；给 `.paper-item-mark` 换边框、调尺寸是安全的，但别改它的布局角色——`academic` / `center` 用 grid 放置、`timeline` 的教育条用 flex 排序，骨架已按这些父级布局写好覆盖。骨架还会用 `display: flow-root !important` 把带徽标的 `.paper-item` 拉回常规流，所以包里给 `.paper-item` 写的 flex 规则不会把徽标栏撑成整行。

模块标题还会带 `.paper-style-<sectionStyle>`，每个模块按类型带 `.is-education`、`.is-work_experience`、`.is-project_experience`、`.is-skill_proficiency`、`.is-custom` 这类类名，可以只给某一类模块加装饰。

**分页与 CSS 的关系**：预览页的虚线断页是浏览器实测出来的，导出 PDF 走同一个组件、同一份 CSS。你的 `style` 改了行高或模块间距，预览与 PDF 会一起变——这正是这套设计要保住的一致性。所以别用 `position: fixed`、`height: 100vh` 这类脱离纸面的写法，打印时它们没有意义。

## 5. 导入 / 导出 / 分享 / 删除

模板包的所有增删操作都集中在**「我的模板」页（`/my-templates`，需登录）**，模板中心和预览页都不提供导入入口：

1. 点「导入模板包」，选一个 `.json`；
2. 校验不过会弹窗逐条列出问题（一次给全，不用来回试）；
3. 通过后它出现在你的「我的模板」里，显示作者、版本、版式与当前有几份简历在用它；
4. 每张卡片两个开关：**分享到模板中心**、**允许他人导出模板包**（后者要先开前者才可选）；
5. 卡片底部：用它新建简历（带着这个模板跳到工作台的新建弹窗）、导出模板包、删除。

预览页的「样式设置 → 模板」分成**官方模板**和**社区模板**两组，社区组包含别人分享的包和你自己导入的包（你自己的那条标「我的」）；模板中心同样按官方 / 社区展示，并显示「某作者 分享」。

规则：

- 导入的模板默认**只有你自己**看得见、用得着。分享到模板中心后，本站所有用户（含未登录访客）才能在模板中心与预览页的社区组里看到并选用它；取消分享只是让它从公开列表消失。
- **导出权限由作者决定**：开着「允许他人导出」时，任何用户（含匿名）都能下载这个包；关掉后别人只能选用，下载按钮换成「仅可使用」，服务端对非作者返回 `403`（未登录 `401`）。官方包永远可导出。
- 取消分享**不会**把别人正在用它的简历打回默认版式：那些简历仍按原样渲染和导出 PDF，也能继续保存样式，只是不能再被新简历选中或换用。
- 还有简历在用的模板删不掉（`409 TEMPLATE_IN_USE`），先给那些简历换模板。
- 同一个人重复导入同一个包（`namespace` + `code` 相同）按版本升级，原地覆盖，分享与导出权限沿用上次的设置；别人占了同一个编码会返回 `409 TEMPLATE_CODE_TAKEN`，改你的 `id.namespace` 或 `id.code` 即可。
- 分享只在**你这个部署站内**发生，没有中央服务器，也不会上传你的预览图。

## 6. 常见报错对照

| 报错 | 原因 | 怎么改 |
| --- | --- | --- |
| `模板包 api=2，当前渲染器只支持 api=1` | 包比程序新 | 找作者要适配本版本的包，或升级部署 |
| `命名空间与编码合成后的「…」不合法或超过 50 字符` | `namespace--code` 太长 | 两边都改短 |
| `official 命名空间保留给…` | 冒用了官方命名空间 | 换成自己的 `namespace` |
| `theme.layout 的值「xxx」不被当前渲染器支持` | 用了还没实现的骨架 | 从 §3 里挑，或按 §7 提 PR |
| `选择器必须以 .tw-xxx 开头` | CSS 越界 | 每条规则前面加自己的作用域类 |
| `url() 只接受 data: 内联资源` | 引了外部图片/字体 | 用 `data:` 内联，或改用 `border`/`background` 画 |
| `style 里有未闭合的注释 / 规则块` | CSS 语法错误 | 本地先过一遍 CSS 校验 |
| `style 超过 16384 字符上限` | 包太大 | 精简；模板包不是塞素材的容器 |

## 7. 新增一套官方模板

内置包放在 `backend/src/main/resources/template-packages/*.json`，文件名即 `id.code`。启动时 `BuiltinTemplatePackages` 读全部包，`DataInitializer` 按编码 upsert：

- 库里没有 → 插入；
- 已有且 `source = builtin` → 比较配置/名称/描述/分类/标签/版本/作者/排序权重，变了才刷新；
- 已有且 `source = imported`（有人导入时占了这个编码）→ **接管升级**：原地刷成内置包内容，`source` 置回 `builtin`，并恢复公开、允许导出；正在用它的简历 `template_code` 不变，跟着换到新版式（预览过的 PDF 缓存随样式版本自动失效）。

官方包可以带 `style`：种子时同样走 `TemplateCssSanitizer` 净化，写进 `config.scopeClass` / `config.styleCss`——18 套由社区模板升级来的官方模板就是这么做的，样式留在 JSON 里而不是 Vue scoped 代码里。

所以新增官方模板就是：

1. 复制一份现有 JSON 改 `id`、`meta`、`theme`、`sortWeight`；
2. 需要新骨架时，按 §3 的三处同步补 `layout` / `sectionStyle`；
3. `mvn -o package` 跑一遍——`TemplatePackageCodecTest` 会校验所有内置包能解码，并钉住 `config` 的键序（键序变了会作废全部 PDF 缓存）。

只改样式不改骨架的模板，不需要动一行 Java。
